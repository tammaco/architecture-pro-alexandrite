# Мотивация

|Система|Почему нужно добавить мониторинг|Что это даст компании|
|-|-|-|
|Messages Queue|Раннее предупреждение о перегрузке|Можно настроить circuit breaker|
|3d files storage|Мониторинг загрузки, количество ошибок, размер очереди на обработку файлов|Можно оптимизировать или предупреждать пользователя при загрузке сложных моделей|
|MES API|Нет информации о времени расчёта заказа|Можно понять, сколько времени занимает расчёт какой модели. Далее появится возможность давать реальные сроки клиентам|
|MES|Нет информации о времени времени по статусам заказа|Поможет выяснить, как быстро операторы берут заказы и скорость производства|

# Выбор подхода к мониторингу

|Система|Подход |Обоснование|
|-|-|-|
|MES API, CRM API, Internet Shop|RED + Четыре золотых сигнала|RED даст информацию по частоте запросов, ошибкам и длительности. Четыре сигнала добавляют Saturation (насыщение connection pool, threads). Это критично при росте нагрузки от партнёров.|
|Messages Queue|USE|Utilization (процент используемой памяти под очередь), Saturation (длина очереди, количество сообщений в RAM), Errors (отказы)|
|MES|RED|Четыре сигнала тут избыточны, это клиентское приложение с пользователем|
|3d files storage|USE|Utilization (используемое место / лимит), Saturation (latency на чтение/запись, количество одновременных загрузок), Errors (403, 500, timeout).|

# Метрики и ярлыки

1. RabbitMQ

|Метрика|Зачем нужна|Ярлыки|
|-|-|-|
|Number of dead-letter letters|Заказы, которые не дошли до MES/CRM|queue, message_type, source_system, destination_system|
|Number of messages in flight|Заказы, которые «в полёте» между системами|queue, message_type|
|Длина очереди по приоритетам (high/medium/low)*|Чтобы видеть, что high (B2C) заказы не тонут среди low (партнёры)|queue, message_type, priority|

2. MES API, CRM API, Internet Shop 

|Метрика|Зачем нужна|Ярлыки|
|-|-|-|
|Number of requests (RPS)|Позволит видеть нагрузку, пики|service, endpoint, method|
|Number of requests (RPS) per user|Позволит видеть и сравнивать нагрузку от пользователей магазина и партнёров|service, endpoint, priority|
|Number of HTTP 200|Для статистики успешных заказов|service, endpoint, priority|
|Number of HTTP 500|Для отслеживания ошибок|service, endpoint, method|
|Number of simultanious sessions|Вывод активности пользователей и партнёров|service, endpoint, method|
|Response time (latency)|Отображение роста задержки на критичных эндпоинтах (заказы)|service, endpoint, method|

3. MES DB, Shop DB, 3d files storage

|Метрика|Зачем нужна|Ярлыки|
|-|-|-|
|Size of S3 storage|Для отслеживание роста объёма 3D‑файлов|bucket, file_type|
|Kb transferred (received) / Kb provided (sent) for shop / CRM / MES API|Для отслеживание сетевого трафика|service|
|Memory Utilisation for Shop db instance / MES db instance|Для контроля чтения из оперативной памяти или диска|db_type|
|Number of connections for shop db instance /  MES db instance|Для выявления увеличения числа подключений|db_type|

4. Дополнительные метрики

|Метрика|Зачем нужна|
|-|-|
|Время расчёта стоимости|Чтобы убедить начальство в необходимости выноса расчёта в воркеры|
|Количество заказов, не дошедших до MES (в CRM создан, но в MES нет)|Поймать птерянные заказы|
