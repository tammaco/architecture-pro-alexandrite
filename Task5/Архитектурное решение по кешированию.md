# Анализ

Так как самым узким местом системы является MES, в первую очередь кэширование нужно внедрить в этой части системы.

1. Результаты расчёта стоимости
Одинаковые модели считаются повторно. Кэширование позволит значительно снизить время расчёта.

2. Дашборд MES
Операторы жалуются на низкую скорость работы со страницей. Каждый раз при загрузке дашборда MES делает тяжёлый запрос к БД.
Кэширование позволит кменьшиьт количетсов запросов.

3. Статусы заказов для API партнёров
Новых клиентов не устраивает скорость выполнения заказа. Партнёры часто опрашивают статусы, создавая нагрузку на CRM, что  создаёт лишнюю нагрузку на CRM и БД.

# Мотивация

Кэширование в первую очередь должно покрыть:

- Результаты расчёта стоимости — самый дорогой процесс

- Дашборд MES — источник боли операторов

- Статусы заказов для API — чтобы не перегружать CRM запросами партнёров

Эти три компонента дадут максимальный эффект при минимальных затратах. После внедрения кэширования:

- Время ответа для повторных заказов упадёт с 30 минут до 5 мс

- Дашборд MES будет загружаться за 100 мс вместо 10 секунд

- Нагрузка на CRM и БД снизится на 70–80%

# Предлагаемое решение

1. Результаты расчёта стоимости

Нужно внедрить серверное кэширование (Redis).
Паттерн - Write-Through. TTL — 24 часа (по частоте изменения цен на драг. металлы).
Инвалидация — при изменении прайс-листа.

**Ключ**: hash(3d_model) + material + size

**Значение**: { price, calculation_time, materials_list, cached_at }


2. Дашборд MES

Нужно внедрить серверное кэширование (Redis).
Паттерн - Refresh-Ahead. TTL — 5 сек. При изменении статуса заказа (CRM публикует событие) кэш обновляется сразу.

**Ключ**: dashboard:{status}:{operator_id} 

**Значение**: список заказов (ID, время создания)

```markdown
[Схема кэширования](https://github.com/tammaco/architecture-pro-alexandrite/Task5/Дашборд MES_кэш.drawio.drawio)
```

3. Статусы заказов для API партнёров

Снова серверное кэширование (Redis).
Паттерн - Cache-Saide. TTL — 1 минута. При изменении статуса кэш обновляется одновременно с БД.

**Ключ**: order_status:{order_id}

**Значение**: { status, last_updated }
